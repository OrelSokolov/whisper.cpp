
## Что означают этапы

### 1. **load time** (1292.53 ms)
- Загрузка модели в память
- **Требует:** ничего (выполняется один раз)
- **Не зависит от размера файла**

### 2. **mel time** (1480.65 ms)
- Преобразование PCM аудио → log mel spectrogram
- Выполняется **один раз в начале** (`whisper_pcm_to_mel_with_state`, строка 6833)
- **Требует:** ВЕСЬ файл (но технически можно делать по частям)
- **Зависит от:** размера аудио файла

### 3. **encode time** (177313.38 ms / 39 runs)
- Кодирование mel spectrogram через encoder
- Выполняется **для каждого чанка** (39 раз в данном случае)
- Внутри основного цикла: `whisper_encode_internal(*ctx, *state, seek, ...)` (строка 7040)
- Использует `mel_offset` для выбора нужной части из уже готового mel spectrogram
- **Требует:** mel spectrogram (может быть готов по частям), но работает с конкретным offset
- **Не требует:** полный файл, работает инкрементально по чанкам

### 4. **decode time** (629.19 ms / 101 runs)
- Декодирование **одного токена** (batch.n_tokens == 1)
- Выполняется в цикле генерации токенов (строка 7518)
- **Требует:** результаты encode (kv_cross)
- **Не требует:** полный файл

### 5. **batchd time** (48034.13 ms / 27015 runs)
- Декодирование **небольшого батча токенов** (1 < batch.n_tokens < 16)
- Выполняется в цикле генерации токенов
- **Требует:** результаты encode (kv_cross)
- **Не требует:** полный файл

### 6. **prompt time** (3527.88 ms / 8557 runs)
- Декодирование **большого батча токенов** (batch.n_tokens >= 16)
- Используется для обработки промпта в начале каждого сегмента (строка 7164)
- **Требует:** результаты encode (kv_cross)
- **Не требует:** полный файл

### 7. **sample time** (18120.41 ms / 27308 runs)
- Выбор следующего токена из лог-вероятностей (`whisper_process_logits`)
- Выполняется после каждого decode
- **Требует:** результаты decode (logits)
- **Не требует:** полный файл

## Порядок выполнения (основной цикл)

```
1. whisper_pcm_to_mel_with_state()  // mel time - ОДИН РАЗ В НАЧАЛЕ
   ↓
2. while (seek < seek_end):
   ↓
   3. whisper_encode_internal(seek)  // encode time - для каждого чанка
      ↓
   4. whisper_decode_internal(prompt)  // prompt time - промпт
      ↓
   5. while (генерация токенов):
      ↓
      6. whisper_decode_internal(1 token)  // decode/batchd time
         ↓
      7. whisper_process_logits()  // sample time
         ↓
      8. (повтор до завершения сегмента)
   ↓
   9. seek += seek_delta  // переход к следующему чанку
```

## Зависимости между этапами

```
load
 ↓
mel (требует весь файл)
 ↓
encode (требует mel spectrogram, работает по чанкам)
 ↓
decode/batchd/prompt (требуют результаты encode)
 ↓
sample (требует результаты decode)
```

## Ответы на вопросы

### 1. Что от чего зависит?

- **mel** → требует весь PCM файл (но технически можно делать по частям)
- **encode** → зависит от mel spectrogram (может работать по чанкам)
- **decode/batchd/prompt** → зависят от encode (kv_cross)
- **sample** → зависит от decode (logits)

### 2. Можно ли начать обрабатывать batchd вместе с энкодером?

**НЕТ**, потому что:
- `batchd` требует результаты `encode` (kv_cross)
- `encode` выполняется для текущего чанка аудио
- `batchd` используется для декодирования токенов, которые генерируются на основе закодированного аудио

**НО** можно параллелизовать:
- Encode для следующего чанка можно начать, пока идет batchd для текущего
- Но это требует буферизации и синхронизации

### 3. Насколько важно иметь сразу ВЕСЬ файл?

**Критично только для:**
- **mel time** - но технически можно делать по частям (с окном перекрытия)

**НЕ критично для:**
- **encode** - работает по чанкам (использует mel_offset)
- **decode/batchd/prompt** - работают инкрементально
- **sample** - работает инкрементально

### 4. Что требует наличие полного файла?

**Только mel spectrogram:**
- `whisper_pcm_to_mel_with_state()` вызывается один раз в начале (строка 6833)
- Принимает весь массив samples и n_samples
- Создает полный mel spectrogram

**Все остальное работает инкрементально:**
- Encode работает с чанками через `mel_offset`
- Decode/batchd/prompt работают с токенами последовательно
- Sample работает с текущими logits

## Возможности для стриминга

### Что можно стримить:
1. **PCM → mel** - можно делать по частям с окном перекрытия
2. **Encode** - уже работает по чанкам (39 runs = 39 чанков)
3. **Decode/batchd** - работают инкрементально

### Что требует синхронизации:
- Encode следующего чанка можно начать параллельно с decode текущего
- Но decode все равно требует завершения encode текущего чанка

### Оптимизация для стриминга:
1. Начать encode следующего чанка параллельно с batchd текущего
2. Преобразование PCM → mel по частям (с перекрытием)
3. Буферизация результатов encode для плавного перехода между чанками

## КАК РЕАЛЬНО РАБОТАЕТ СТРИМИНГ В ПРОЕКТЕ

### Примеры: `examples/stream/stream.cpp`, `examples/command/command.cpp`

**ОНИ НЕ ДЕЛАЮТ НАСТОЯЩИЙ СТРИМИНГ!** Вот что происходит:

```cpp
// Строки 278-291 stream.cpp
// 1. Собирают новый кусок аудио
audio.get(params.step_ms, pcmf32_new);  // например, 3000 ms

// 2. Берут часть старого аудио для контекста (params.keep_ms = 200 ms)
const int n_samples_take = std::min(
    (int) pcmf32_old.size(), 
    std::max(0, n_samples_keep + n_samples_len - n_samples_new)
);

// 3. Склеивают: [старый кусок] + [новый кусок]
pcmf32.resize(n_samples_new + n_samples_take);
for (int i = 0; i < n_samples_take; i++) {
    pcmf32[i] = pcmf32_old[pcmf32_old.size() - n_samples_take + i];
}
memcpy(pcmf32.data() + n_samples_take, pcmf32_new.data(), ...);

// 4. ВЕСЬ склеенный кусок отправляют в whisper_full()
whisper_full(ctx, wparams, pcmf32.data(), pcmf32.size());
```

### Это "псевдо-стриминг":
- Собирают аудио кусочками (например, каждые 3 секунды)
- К каждому новому куску добавляют немного предыдущего (200ms для контекста)
- **Весь склеенный кусок** (~3.2 секунды) отправляют в `whisper_full()`
- `whisper_full()` делает **полный цикл**: mel → encode → decode
- Повторяют для следующего куска

### Параметры стриминга:
- `--step 3000` - как часто брать новый кусок (3 сек)
- `--length 10000` - размер обрабатываемого окна (10 сек)  
- `--keep 200` - сколько оставлять из прошлого для контекста (200ms)

### Почему mel не проблема:
**Потому что они обрабатывают МАЛЕНЬКИЕ куски!**
- Если кусок 3 секунды → mel time будет ~150ms вместо 1480ms
- Если кусок 10 секунд → mel time будет ~500ms
- Масштабируется линейно с размером куска

### Почему encode делается 39 раз в вашем примере:
**Потому что файл был ДЛИННЫЙ!**
- Файл = ~260 секунд (250 сек total time / ~0.96 realtime factor)
- 39 runs encode → ~260/39 = ~6.7 секунд на чанк
- Это внутренние чанки Whisper (30-секундные окна обработки)

### Настоящий порядок при стриминге:

```
[Микрофон] → накопление 3 сек
    ↓
[Обработка куска 3 сек через whisper_full()]
    mel (150ms) → encode (1-2 runs) → decode → sample
    ↓
[Результат текста]
    ↓
[Микрофон] → накопление следующих 3 сек + 200ms overlap
    ↓
(повтор)
```

### Итого:
- **Требуется полный файл** = требуется полный ТЕКУЩИЙ КУСОК
- Для стриминга просто делают куски маленькими (3-10 секунд)
- Каждый кусок обрабатывается полностью и независимо
- Добавляют overlap (200ms) для плавности между кусками

## РЕЗЮМЕ: Ответы на вопросы (исправленные)

### 1. Что от чего зависит?
**Два уровня обработки:**

**Уровень приложения (stream.cpp):**
- Собрать кусок аудио (3-10 сек)
- → Передать в `whisper_full()`

**Уровень whisper_full() (внутренний):**
- mel (требует весь кусок, ~5% времени)
- → encode (работает внутренними чанками по 30 сек, 70% времени)
- → decode/batchd/prompt (зависят от encode, 20% времени)
- → sample (зависит от decode, 7% времени)

### 2. Можно ли начать обрабатывать batchd вместе с энкодером?
**НЕТ для одного куска** - batchd требует результаты encode.

**ДА для параллельной обработки нескольких кусков:**
- Обрабатывать encode куска N+1 пока идет decode куска N
- Но это требует параллельных контекстов

### 3. Насколько важно иметь сразу ВЕСЬ файл?
**Совсем не важно!**
- Просто режь файл на куски по 3-10 секунд
- Каждый кусок обрабатывай через `whisper_full()` независимо
- Добавляй 200ms overlap между кусками для плавности
- Именно так работает `examples/stream/stream.cpp`

### 4. Что требует наличие полного файла?
**Ничего не требует полный файл целиком!**
- Каждый вызов `whisper_full()` обрабатывает свой кусок независимо
- mel создается только для текущего куска
- encode обрабатывает текущий кусок (может разбить на внутренние чанки)
- Никакого глобального состояния между вызовами `whisper_full()`

### Вывод для стриминга файлов:
Если хочешь стримить большой файл:
1. Читай файл кусками по 3-10 секунд
2. Для каждого куска вызывай `whisper_full(pcmf32.data(), pcmf32.size())`
3. Добавляй 200ms overlap с предыдущим куском
4. Всё. Это и есть стриминг в whisper.cpp

**Пример:**
```cpp
// Вместо:
whisper_full(ctx, params, full_file_samples, full_file_size);  // ❌

// Делай:
for (int offset = 0; offset < full_file_size; offset += chunk_size - overlap) {
    int chunk_len = std::min(chunk_size, full_file_size - offset);
    whisper_full(ctx, params, &full_file_samples[offset], chunk_len);  // ✅
}
```

## Детали реализации

### Как encode работает с чанками

```cpp
// whisper_encode_internal() использует mel_offset для выбора нужной части
const int i0 = std::min(mel_offset,           mel_inp.n_len);
const int i1 = std::min(mel_offset + 2*n_ctx, mel_inp.n_len);

// Берет только нужный диапазон из готового mel spectrogram
for (int j = 0; j < mel_inp.n_mel; ++j) {
    for (int i = i0; i < i1; ++i) {
        dst[j*2*n_ctx + (i - i0)] = mel_inp.data[j*mel_inp.n_len + i];
    }
}
```

**Важно:** encode НЕ требует полный файл - он работает с уже готовым mel spectrogram по частям.

### Классификация decode/batchd/prompt

```cpp
// В whisper_decode_internal() (строки 2984-2993)
if (batch.n_tokens == 1) {
    wstate.t_decode_us += ...;  // decode time
} else if (batch.n_tokens < 16) {
    wstate.t_batchd_us += ...;  // batchd time
} else {
    wstate.t_prompt_us += ...;  // prompt time
}
```

- **decode**: 1 токен
- **batchd**: 2-15 токенов
- **prompt**: 16+ токенов
